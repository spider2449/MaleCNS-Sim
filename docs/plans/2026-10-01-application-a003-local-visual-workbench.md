## A003R recertification boundary

The CPU and CUDA engines iterate `range(N)` for `N = duration_ms / dt_ms` exact grid updates and record a spike from loop step `k` as `k + 1`. Legal spike timesteps are therefore integer `1..N`, including `N`; zero, negatives, nonintegers, NaN/Infinity, and `N + 1` are rejected by A002. Equal-timestep spike ordering remains canonical by `(timestep, neuron ID)`. The bounded selection deterministically sets the experiment UUID, so Validate and Run must produce identical canonical `ExperimentSpec` bytes and digests; the job/invocation IDs remain execution metadata. The historical failed run above is unchanged.

## Scope and launch

Run `uv run malecns-workbench` from the repository root, then open the printed URL. The stdlib server binds `127.0.0.1:8765`; `--port 0` chooses an ephemeral loopback port. If the three registered Feather files are absent, the shell still opens and reports `DATASET_UNAVAILABLE`. No downloads occur. A trusted operator can set `MALECNS_DATA_ROOT` to a local data directory; the browser never supplies a path.

## Boundary

The browser sends a six-field bounded selection. The Python catalog supplies pinned dataset, graph and mapping identities; frozen sugar identities come from A002's engine adapter. A002 owns spec validation, run identity, execution, events, error categories, result serialization and integrity. The server does not call the engine directly. The CPU reference backend is available without CuPy. The CUDA option is enabled only when `ProductionEngine.cuda_available()` enumerates a device.

The server checks Host and Origin, requires a per-process URL-fragment token on mutation, and limits JSON requests to 2 KB. It exposes no arbitrary paths, commands, imports, or upload route. `GET /api/status`, `/api/datasets`, `/api/experiment/options`, `/api/runs`, `/api/runs/{job}`, `/api/runs/{job}/events`, `/api/runs/{job}/result`, and `/api/runs/{job}/export`; `POST /api/experiments/validate` and `/api/runs`. A job ID identifies one invocation; the A002 run ID appears once execution starts. One run is active at a time and eight jobs remain inspectable during the process lifetime. The event transport is bounded polling. The export is a checked backend manifest under a controlled temporary result root.
